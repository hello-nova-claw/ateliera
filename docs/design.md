# Ateliera design record

This is the design record. It says what Ateliera must always be, how it is built, and which options were turned down and why. [CONTRIBUTING.md](../CONTRIBUTING.md) holds the working rules; [docs/privacy.md](privacy.md) holds the data-handling detail.

## 1. What Ateliera is

Ateliera is a private journal for designing a life from the inside out. It holds journal entries, reflections, dreams, gratitude, intentions and possibilities, and it sets them against the season, the moon and the user's own cycle.

It ships as two apps that share a file format and no code:

- a native SwiftUI app for iPhone and iPad (and Mac, later), in `apple/`;
- a web app (PWA) and a Tauri desktop app, in `apps/` and `packages/`.

Both use the same **vault** format: Markdown files and ordinary media that the user owns. The Apple and desktop apps keep the vault in a folder the user picks. The browser keeps it in the browser's private storage, and the user moves it in and out by export and import.

## 2. Design principles (not negotiable)

These hold for every change. A pull request that breaks one is closed, however good the code is. Changing a principle needs a decision from Anna, recorded in section 5.

1. **The data stays with the user.** Entries live as files in a vault the user owns. Ateliera sends nothing to its developer or to any third party. The only data that leaves the device goes to Apple services the user has turned on, each named in [docs/privacy.md](privacy.md), or goes where the user sends it: their own iCloud Drive if the vault is kept there, a backup they export or share, or a link they open.
2. **No accounts, no analytics, no ads, no tracking.** No third-party SDK that collects anything, ever.
3. **No medical or contraceptive claims.** Cycle days and phases are estimates from the user's Health data, and the app says so wherever it shows them.
4. **Export everything, delete everything.** The user can export all their data in an open format, and delete all of it, in two taps each.
5. **No guilt.** No streaks, overdue badges, punishing counts, guilt notifications or dark patterns.
6. **AI on the device only, speaking to the user.** Any model runs on the device. It may suggest, reflect and ask. It never writes the journal for the user, and nothing it produces is saved as if the user wrote it.

These are requirements, not a description of today's code. Where the apps fall short, [docs/privacy.md](privacy.md) names the gap and its issue.

## 3. Architecture

### The vault

- A vault is a folder. Notes are Markdown files with YAML frontmatter. Media are ordinary files beside them.
- The Markdown files are the source of truth. Everything else (the search index, caches, projections) can be rebuilt from them without loss.
- Every note carries `schema_version: 1`. The frontmatter schema is defined in `packages/content/src/frontmatter-schema.ts` and mirrored in `apple/Ateliera/Note/NoteParser.swift`.
- Unknown frontmatter keys survive every read and write, in their original order.
- App state that belongs to the vault lives in its `.studio/` folder: settings, configuration, views, revisions (`backups/`), trash, caches and export manifests. Some state stays on the device instead, in `UserDefaults` (Apple) or `localStorage` and `sessionStorage` (web). [docs/privacy.md](privacy.md) lists it.
- A note is a single piece of text. With no `title` key, its first non-empty line is its title for display, links, backlinks and search.

### Writes

- Every vault write is atomic (temp file, sync, rename), contained in the vault (no path can escape the root), validated and recoverable from a revision.
- Files the app writes outside the vault, such as the export ZIP, are listed in [docs/privacy.md](privacy.md) with how they are written.
- On Apple platforms the Rust vault core in `apple/AtelieraVaultCore` performs these writes. Swift calls it through UniFFI. The Tauri app uses the same approach in `apps/studio/src-tauri`.

### The two apps

- **Apple app (`apple/`).** SwiftUI, generated by XcodeGen from `apple/project.yml`. It has a widget extension and one App Intent. iOS and iPadOS 17 and macOS 14 are the minimums. The vault is a folder the user picks, kept as a security-scoped bookmark.
- **Web and desktop app (`apps/studio`, `packages/*`).** React 19, Vite, a service worker, and Tauri for desktop. The packages are layered strictly, and ESLint enforces the layering. The search index is SQLite FTS5 in a Web Worker, and it is disposable.
- **Shared contract.** The apps share the vault format, not code. Every shared algorithm is golden-matched: the note schema and Markdown round-trip, projections, resurfacing, search and link repair, ZIP export and import, and the rhythm calculations. Expected values for Swift tests are taken from the TypeScript packages.

### Rhythm

- Seasons, solstices and moon phases are computed on the device from Jean Meeus's formulas. Nothing is fetched.
- In the Apple app, the cycle is read from Health (menstrual flow only), on the device, and kept in memory. It is never written to the vault. One derived trace persists on the device: a dismissed cycle invitation's ID, in `UserDefaults`, names the phase it was shown in.
- The web app has no Health access. The user can type a last period start and an average length, which are stored in the vault's rhythm profile (see #151).
- The natal chart is computed on the device from birth details the user types in.

### On-device AI

- One feature uses a model: personalised micro-season wording, through Apple's Foundation Models framework, on the device.
- Its input is the season, moon, climate band, hemisphere and home place. It never sees journal text, cycle data or birth details.
- Its output is shown as the season's wording and cached in the vault. It is never written into a note.
- Without the model, the app falls back to the standard wording. Every feature works offline and without AI.

## 4. Product invariants

- Markdown and media are authoritative; indexes and caches are disposable.
- Vault writes are atomic, path-contained, schema-validated, recoverable and tested.
- Unknown YAML keys survive.
- Core behaviour works offline and without AI.
- No streaks, overdue badges, gamification, compulsory check-ins or guilt-inducing counts.

## 5. Decisions

Each decision records what was chosen, what was rejected, and why, so rejected options don't come back.

### No analytics, crash-reporting, advertising or attribution SDK, ever

Rejected: Firebase, Sentry, TelemetryDeck and any similar tool, including "privacy-friendly" analytics. A journal of this kind must not phone home, and crash reports can carry entry text. Apple's own opt-in crash reports through App Store Connect are enough.

### Sync is the user's own iCloud Drive folder, not CloudKit or a server

Rejected: CloudKit and any backend. The vault is a folder of files, so the user chooses where it lives. If that is iCloud Drive, Apple syncs it to their own account. Ateliera runs no server and holds no copy.

### HealthKit is read-only, and cycle data is never stored

The Apple app reads menstrual flow from Health, works out the cycle in memory, and writes nothing to Health or to the vault. App Review Guideline 5.1.3 forbids storing personal health information in iCloud. A vault can live in iCloud Drive, so Health data must never enter it. Rejected: logging periods inside the Apple app, and caching the derived cycle. The web app's typed-in cycle dates are an open question (#151).

### No medical or contraceptive features

Rejected: fertility windows, ovulation prediction as a feature, and contraception support. These need medical-device standards the app does not meet, and wrong answers harm people.

### Location is optional, and lookups go to Apple

The hemisphere and home place can come from one location fix or from a place the user types. Turning a place into coordinates uses Apple's geocoder, which sends the place name or coordinates to Apple. This is disclosed in [docs/privacy.md](privacy.md). Rejected: third-party geocoding and IP lookups.

### One repository for both apps

Considered: separate repositories for the Apple app and the web app. Kept together because the Swift tests are golden-matched to the TypeScript packages, and the vault format is the contract between them. CI runs each app's jobs only when its paths change.

### Licensing: MIT code, reserved content

The code is MIT licensed ([LICENSE](../LICENSE)). The name, icon and the app's written content are all rights reserved ([CONTENT-LICENSE.md](../CONTENT-LICENSE.md), [TRADEMARKS.md](../TRADEMARKS.md)). The repository is public so that anyone can check that the data really stays on the device. A reserved name, icon and writing stop a public repository from becoming a clone in the App Store. Contributions are accepted under MIT; written content and artwork need a written agreement first. Decided by Anna on 26 October 2026.

### Process: Novaclaw, issues first, CodeRabbit review

Work is done by agent sessions under the Novaclaw GitHub account and reviewed by CodeRabbit, following [CONTRIBUTING.md](../CONTRIBUTING.md), the same system as Anna's Undergrowth repository. Anna is the code owner and decides anything that touches the principles. Decided on 26 October 2026.

### First release: iPhone and iPad, through TestFlight

The first release is iPhone and iPad. The Mac app follows in 1.1. A TestFlight beta comes before the App Store. Builds are uploaded by hand for 1.0. An automatic upload from CI, using an App Store Connect key held as a repository secret, may come later.
